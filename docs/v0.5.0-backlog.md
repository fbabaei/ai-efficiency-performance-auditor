readiness claim. The active methodology is the unreleased 0.5.0 candidate.
Keep the chosen shared VS Code/CLI/experimental-cloud profile and explicit user
selection. Preserve read-only evidence, report-only Markdown creation, privacy,
sanitization and current exploration caps.

## Coverage and decisions

The [automated/manual coverage map](../evaluations/README.md#automated-and-manual-coverage)
separates executable output checks, existing session/accounting checks, and
unrun host/semantic acceptance. Do not turn a checker-oracle pass into a live-run
pass or treat declaration assertions as enforcement.

Decisions retained from the review:

- Keep one shared profile rather than selecting VS Code-only or creating
  divergent profiles. Cloud behavior remains experimental until HOST-01 passes.
- Keep discovery paths inside the hard budget. Do not cap displayed results and
  silently discard surplus paths; DISC-01 investigates usability before changes.
- Keep six report sections. Coverage/provenance belong in the Verdict, not
  an additional unbounded appendix.
- Do not overwrite or repair created files after partial/invalid writes.
  Return corrected Markdown in Chat and disclose the failed artifact.
- Keep evaluation acquisition, computation and persistence in the runner.
  The auditor neither executes these checkers nor writes JSON evidence files.
- Keep methodology 0.5.0 marked unreleased until release acceptance. The internal
  advisory-evidence/1 and advisory-markdown/1 contracts do not version historical
  checker schemas or retroactively validate prior captures.
